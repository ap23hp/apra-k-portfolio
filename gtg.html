The brief

Client had the design.
They needed the code.

GTG Perfumes came with a finished Figma file and one hard requirement — no Elementor, no page builders, no bloated plugin stack. They'd been burned before by themes that broke on updates and third-party plugins that slowed the site.

They needed a developer who could read a Figma file and ship clean, maintainable HTML/CSS/JS that would work with their existing WooCommerce setup without adding any dependencies.

"We had the design ready. We just needed a developer who could build it clean — no page builders, no shortcuts, nothing that'll break in six months."

The challenge

Four problems
to solve.

A standard WooCommerce setup couldn't handle the subscription logic without heavy plugin customisation — and every plugin added load time and maintenance overhead the client didn't want.

01
9 cart combinations
Two plans × three fragrances each = nine cart states. Each needed its own dynamic WooCommerce cart URL, updated in real time without page reload.
02
Expand / collapse UI
Single and double subscription cards had to expand and collapse as the user switched plans — revealing fragrance pickers and benefits without layout shift.
03
Synced image gallery
Prev/next arrows, dot navigation and four thumbnails — all had to keep the main image, dots and thumbs in perfect sync at all times.
04
3 breakpoints from scratch
The Figma file was desktop-only. Mobile and tablet layouts had to be designed and implemented from first principles — no specs provided.
The build

What I built.

01
Dynamic cart URL builder
A JS function reads the active plan and fragrance radios on every change and constructs the correct query-string URL in real time, updating the Add to Cart href. Works with any WooCommerce endpoint — zero plugin dependency.
/cart?plan=double&fragrance1=original&fragrance2=lily
02
Subscription expand / collapse
On radio change, all cards reset to collapsed and the selected card gets an active class — revealing hidden content via a single CSS class toggle. No animation library, no framework.
03
Gallery with full sync
A single updateSlider(index) function updates the main image src and toggles active classes on dots and thumbnails simultaneously. Arrows wrap at boundaries using modulo arithmetic.
04
Accordion with icon swap
Collection section with single-open logic — clicking any item closes all others first, then toggles the current one. The plus/minus SVG src is swapped on each state change.
05
Viewport-triggered stats counter
IntersectionObserver fires the counter animation only when the stats section enters the viewport — counting up to the data-target value using requestAnimationFrame. Re-triggers on each re-entry.
06
Full responsive layout
Three breakpoints built from scratch: desktop (1440px grid), tablet (768–1024px stacked layout), and mobile (single-column, hamburger nav, touch-friendly fragrance options). No mobile Figma specs — designed and built independently.

Reflection

What I took away.

Vanilla JS is enough
Every interaction was built with zero libraries. Sliders, accordions, counters, cart logic — the DOM API handles all of it cleanly. Reaching for a framework first is often the wrong instinct.
State lives in the DOM
Checked radio inputs and active CSS classes are the source of truth. The cart URL builder just reads the DOM on every change — simpler and less error-prone than maintaining a separate JS state object.
The Figma handoff gap is real
The desktop file had zero mobile specs. Designing the responsive layouts from first principles is a skill clients at this level consistently need — and don't always know to ask for.
Plugin-free WooCommerce integration
The cart URL builder is a pure JS function that drops into any WooCommerce theme with one script tag. No plugin, no shortcode, no theme dependency. That's the kind of clean delivery clients remember.
