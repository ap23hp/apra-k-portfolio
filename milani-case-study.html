The brief

One website.
Twelve cities. Infinite scale.

Milani Electrical & Solar services 12+ Canadian cities. They needed a website that could serve location-specific content, show the right phone number, and automatically detect which city a visitor was in — all without creating 100+ manual pages.

Traditional approaches would mean duplicating content, managing separate WooCommerce products per city, and manually updating 144 pages whenever a service changed. They needed architecture that scales automatically.

"We needed something that could handle 12 cities without us manually creating pages for each one. And it had to be fast."

The challenge

Seven problems
in one architecture.

Standard WordPress can't handle multi-location routing, dynamic geolocation, or the complex URL structures needed for city-specific content without serious customization. Every approach had trade-offs between performance, maintainability, and scalability.

01
Multi-location URLs
Each city needs clean URLs: /vancouver/, /calgary/ev-chargers/. That's 80+ service pages without creating physical pages.
02
Smart geolocation
Detect visitor's city via GPS → Google API → IP → postal code fallback. All in real time, without blocking page load.
03
Custom content per city
Phone numbers, service availability, and messaging change by location. Manage it from one config file.
04
SEO & structured data
Each city page needs LocalBusiness schema, BreadcrumbList, Service markup — all dynamic from one template.
05
Lead tracking
Capture form submissions with city + service metadata. Track which cities convert best.
06
Core Web Vitals
Multi-location sites often suffer from bloated third-party plugins. Goal: <2s LCP, <50ms FID, <0.1 CLS.
07
Theme independence
All logic must live in the plugin. Changing themes shouldn't break anything.
The build

Custom WordPress plugin architecture.

01
Custom Post Type System
Two CPTs: City and City Service. Coupled with intelligent URL rewrite rules that detect city + service combinations and map them to the correct post. No manual page creation.
register_post_type( 'city', [...] )
02
Advanced rewrite rules
Regex-based URL routing with automatic flushing when city data changes. Fallback logic prevents broken routes. Guards against canonical redirect issues.
add_rewrite_rule( '^(city)/([^/]+)/?$', 'index.php?post_type=city&name=$matches[1]' )
03
3-tier geolocation engine
Tier 1: Browser GPS → Google Geocoding. Tier 2: IP detection with transient caching (reduces API calls by 80%). Tier 3: Manual postal code search with Haversine distance formula.
04
Dynamic shortcodes
Four shortcodes personalize content: [milani_city], [milani_phone], [milani_service], [milani_map]. Works with any theme, fully portable.
do_shortcode( '[milani_phone]' )
05
JSON-LD structured data
Dynamic schema generation for LocalBusiness, Service, BreadcrumbList, PostalAddress. Detects Yoast and injects into its schema graph if active. Zero plugin conflicts.
06
Custom lead capture system
Database-backed form submissions with city + service metadata. Admin dashboard for lead review. Email notifications on new submissions. No third-party form plugin required.
07
Google Tag Manager & Conversion API
Event tracking for form submissions, phone clicks, and page views. Attribution clarity across all 12 cities. Connected to Google Ads for ROAS measurement.

Optimization techniques

What made it fast.

Image optimization & lazy loading
Native loading="lazy" on all images. WebP format for modern browsers with JPEG fallback. Responsive srcsets for mobile/tablet/desktop reduce payload by 40%.
Deferred JavaScript loading
Non-critical JS loads asynchronously. Geolocation timeout set to 3 seconds — if IP detection is slow, page doesn't block. Critical CSS inlined in header.
Transient caching strategy
IP geolocation results cached by /8 subnet with 24-hour TTL. Coordinates cached in transients. Reduces external API calls by 80% after first visit.
Database optimization
Indexed city/service columns on custom form table. Prepared statements prevent N+1 queries. Minimal database footprint — the plugin adds only 4KB of overhead.
Zero plugin bloat
Every feature built custom instead of relying on third-party plugins. No dependencies = no version conflicts, no security vulnerabilities, no unexpected performance hits from plugin updates.

What I learned

Key takeaways.

Architecture matters more than plugins
The difference between a bloated site and a fast one is thoughtful architecture, not more plugins. Custom code built cleanly beats plugin stacks every time.
Geolocation is a feature, not a hack
With proper caching and fallbacks, geolocation can be fast and reliable. The 3-tier approach handles edge cases without sacrificing performance.
Web Vitals require holistic thinking
Hitting LCP targets means addressing images, JS, CSS, geolocation timeouts, and API performance simultaneously. No single fix solves the problem.
Multi-location sites are complex, but solvable
The architecture pattern here (CPTs + rewrites + dynamic content) applies to any multi-location business. It's more scalable than Elementor or page builders.
